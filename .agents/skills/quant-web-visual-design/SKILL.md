# Web 页面视觉设计

先读对应需求的 PRD、交互原型和已有视觉稿。PRD 决定功能与业务状态，原型决定交互；效果图只表达视觉方向。没有已认可的设计时，从当前需求建立方向，不把原型 CSS 当作长期视觉规范。

## 新页面或新视觉方向

1. 列出需要呈现的页面及关键状态，优先正常、空数据、校验失败、停用或不可用、保存成功。只画本次需求真实存在的能力。
2. 定义信息层级、布局密度、桌面常用宽度及窄窗口行为；从已有页面或参考图提取可复用的颜色、字体、间距和组件规则。参考图提供视觉线索，不决定产品功能。
3. 先给出简短视觉方向，再生成所需的少量效果图。生成或编辑位图时使用 `imagegen` Skill 与图像工具；图像中出现的数值、状态和环境标签须符合需求。

## 基于已有设计局部调整

确定作为母版的已认可效果图或页面，写清“保持不变的区域”和“本次改变的区域”。只改有依据的局部；若变化影响信息层级或交互，先说明，再按授权范围更新需求与原型。

## 设计交接与检查

在需求目录保存效果图和一份简短 `design.md`，记录设计来源、页面结构、主要视觉规则、关键状态、窄窗口行为及仍待确认的点；在需求索引中链接实际产物。形成跨页面稳定规则后，再集中写入 `docs/design/`，避免每个需求复制一套 Token。

检查实际图像的可读性、文本溢出、表格密度、操作显著性和回测／模拟／实盘标识；不能只检查生成提示词。用户选用 Penpot 时可制作可编辑稿，但不把 Penpot 设为默认前置步骤。实现交给 `quant-feature-development`，并按已确定设计核对页面。

尊重用户要求的阶段；只请求效果图时不写前端代码。不为普通页面建立逐控件编号或逐像素合同，只有复杂组件确需精确交接时才增加相应细节。
