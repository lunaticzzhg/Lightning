# 量化平台测试用例设计

先确定被测需求、测试层级、实际入口和可观察结果。读取 PRD、适用的原型／页面设计及必要技术合同；不要把方案中的内部机制直接当成用户可见结果。

## 选用例

- 每项关键需求和重大风险至少有一条可判断通过或失败的用例；优先选择能暴露真实错误的正常、边界、失败和恢复路径，删除重复覆盖。
- 交易相关用例按本需求核对环境隔离、参数和数据版本、订单／成交、成本、报表及对账；只要求当前测试层级能够实际控制和观察的内容。
- 区分成功、处理中、失败和未覆盖。没有可执行入口或可观察证据时，标出缺口及所需的下一层验证，不猜测结果。

## 写法与检查

每条用例写清编号、前提（仅必要时）、操作、可观察预期和待记录的结果。操作与预期分开；预期应让执行者无需猜测即可判断。使用者指定格式时遵从，否则用简短表格或列表，不强制思维导图。

交付前对照需求编号检查覆盖范围，确认测试数据可准备、操作可执行、结果可观察。只设计用例时不运行测试，不写“通过”；实际执行结果留给需求测试报告。
