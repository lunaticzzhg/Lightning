# 量化流程审视

以一个用户动作或外部事件到可观察结果的完整流程为单位。默认只读；先还原当前事实，再评价，不按类的行数或测试数量直接判断质量。

## 还原流程

1. 明确范围和目标，读相关 PRD、技术方案、源码、直接调用方及测试。区分文档计划、源码事实与实际验证。
2. 画出入口 → 决定者 → 权威状态及写入方 → 外部副作用 → 页面或报表结果。指出正常结束位置和第一排障检查点。
3. 只检查真实可达的异常：失败、重复、取消、迟到结果、重启或恢复。交易流程特别核对环境、账户、订单／成交事实、成本与对账依据。

## 判断与输出

检查是否存在无人负责的结果、多个写入方、无法结束的任务、错误数据归属，或必须跨过多层纯转发才能定位问题。静态复杂度只用于选择阅读位置，不能单独证明需要重构。

输出简短结论：流程和事实依据、已证实的问题、实际后果、最小修正方向、验证方式及证据缺口。证据不足时写“未验证”，不把推断写成缺陷。没有问题时说明已核对的范围，不制造整改项。

需要改代码时转 `quant-feature-development`。局部行为保持重构应先固定输入、输出与失败行为；改动应减少需要掌握的状态或跨层跳转，而非只拆文件或增加包装类。
